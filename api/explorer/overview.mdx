The Explorer API exposes the data behind [Compliance Explorer](/explorer/overview) to exchange integrators. With a scoped key you can stream tokenomics change revisions and run your own [Disclosure Monitoring](/tools/disclosure-monitoring) watchlist from code — watching assets, reading detected changes and pulling the notification inbox.

```text Base URL
https://explorer-api.bluprynt.com
```

## Key concepts

| Term | Meaning |
|---|---|
| Exchange key | A `bx_live_…` bearer token Bluprynt issues per integrator. Scoped, rate-limited, revocable. |
| Scope | A permission on the key: `tokenomics:read`, `monitoring:read`, `watchlist:write`. |
| Watchlist | Your set of watched registry assets. Monitoring and notifications cover only what you watch. |
| Change | A detected difference on a watched asset — a disclosure field edit, register move, sanctions listing, and so on. |
| Tokenomics revision | A verified change to an asset's tokenomics — unlocks, emissions, allocations, control — with issuer and on-chain evidence. |

## Endpoints

Eight routes are key-callable. Everything else — the full registry read surface — serves the public explorer frontend, not keys.

| Endpoint | Scope | Returns |
|---|---|---|
| `GET /tokenomics/changes` | `tokenomics:read` | Tokenomics revisions across your watchlist. |
| `GET /assets/{id}/tokenomics/changes` | `tokenomics:read` | Tokenomics revisions of one asset. |
| `GET /me/watchlist` | `monitoring:read` | Your watchlist with limit and usage. |
| `POST /me/watchlist` | `watchlist:write` | Watch a registry asset. |
| `PATCH /me/watchlist/{id}` | `watchlist:write` | Pause/resume monitoring, edit the note. |
| `DELETE /me/watchlist/{id}` | `watchlist:write` | Stop watching. |
| `GET /me/monitoring/changes` | `monitoring:read` | Detected changes on your watchlist. |
| `GET /me/notifications` | `monitoring:read` | Your notification inbox. |

<Warning>
The three `watchlist:write` routes change your watchlist. Everything else is read-only.
</Warning>

## Authenticate

Bluprynt issues exchange keys by arrangement — ask [product@bluprynt.com](mailto:product@bluprynt.com). Send the key as a bearer token:

```bash
curl -s "https://explorer-api.bluprynt.com/me/watchlist" \
  -H "Authorization: Bearer bx_live_your_key_here"
```

A route answers only when your key holds its scope. See [Authentication and scopes](/api/explorer/authentication).

## Check the service

Two routes need no key:

```bash
curl -s https://explorer-api.bluprynt.com/health
# {"status":"ok","info":{},"error":{},"details":{}}

curl -s https://explorer-api.bluprynt.com/openapi.json | jq .info.title
# "Compliance Explorer Registry API"
```

## Response envelope

Key-callable routes wrap their payload:

```json
{
  "data": { "…": "the route payload" },
  "meta": { "request_id": "req_…", "fetched_at": "2026-10-07T20:00:00.000Z" },
  "errors": []
}
```

Errors instead carry a stable `code` — see [Errors](/api/explorer/errors).
